## 結論：読むと何が得できるか

- **待ち時間が消える** — 制限に達しても、リセット後は自動で続きから始まる。時計を見て待つ作業がなくなる
- **長時間タスクを安心して任せられる** — 寝ている間・外出中でも作業が止まらない。翌朝には続きが進んでいる
- **トークンも無駄にしない** — 公式が教える節約の工夫を使えば、同じ制限の中でもっと多くの作業を進められる

大事なのは「オートコンティニューを使うかどうか」だけではなく——**長時間タスクをどう設計し、トークンをどう使うか**まで含めた運用の工夫です。対象範囲や確度の注意は[最新情報](#最新情報オートコンティニュー-チェックボックス)と[FAQ](#faq)にまとめました。

## 長時間稼働の工夫

Claude Code公式ドキュメント「[Run Claude Code programmatically](https://code.claude.com/docs/en/headless)」（headless mode）から。✅

- `-p`（`--print`）: 非対話でプロンプトを処理し、結果をstdoutに出力して終了する実行方式
- `run_in_background: true`: devサーバー等の長時間プロセスをバックグラウンドタスクとして起動しつつ作業を継続。`/tasks`で一覧・停止できる
- `-p`実行中にバックグラウンドタスクを開始した場合、結果出力後5秒の猶予で終了。ただしバックグラウンドサブエージェント・ワークフローは最終出力の一部として扱われ、`-p`はその完了を待つ（v2.1.182以降は既定で最大10分でタイムアウト）
- 大きなタスクはサブエージェントに切り出し、本体とは別のコンテキストで処理する

## トークンを使いすぎない工夫

Anthropic公式ブログ「[Maximizing the value of your Claude Code sessions](https://claude.com/blog/maximizing-the-value-of-your-claude-code-sessions)」（著者: Lydia Hallie、2026年8月14日公開）から。✅

- `/clear` — 無関係な過去のコンテキストを送り直さないことでトークン消費を削減
- `/compact` — キーボードから離れる前に実行。プロンプトキャッシュは1時間で失効するため、キャッシュが生きているうちの要約は安価
- `/rewind` — 直近の不要なターンだけを切り捨てる。コンパクトより低コスト
- `/context` — セッション開始時に1回実行し、CLAUDE.md・MCPツール定義など何が読み込まれているか確認、不要な分を削除
- `/mcp` — 使わないMCPサーバーの起動を止める
- `/model` `/effort` はセッション開始時に決め、**途中変更しない**（変更するとプロンプトキャッシュが失効しコスト増）

**キャッシュ価格の目安**（一気にやる方が経済的、という根拠になる数字）: キャッシュ読み取り＝入力価格の**0.1倍**／キャッシュ書き込み＝通常入力の**最大2倍**／出力トークン＝入力の**約5倍**。CLAUDE.mdは**セッションのたびに毎回**読み込まれるため、5,000トークンのCLAUDE.mdは書く前から毎回5,000トークンのコストになります。
